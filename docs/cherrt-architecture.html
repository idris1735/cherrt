The path of a single message

What happens when someone texts

Nothing is stored or acted on until consent is given and the safety layer clears it. The AI only ever calls typed, role-checked tools — it never touches the database directly.

Inbound webhook→ De-dupe→ Consent gate→ Resolve identity & church→ Scam / danger check→ Agent loop (step-capped)→ Role-checked tool→ Supabase (service-role)→ Reply + delivery log

Roles & powers — the authority ladder

Each rung unlocks everything below it. Powers come from a tool's minimum rank; anything holding personal data is gated separately — and read-only for the IT role, always.

The rails it can't cross

Rules & guardrails

These are enforced in code and locked by tests — the AI stays sharp and reactive, but never autonomous over money, minors, or personal data.

Consent first

No data stored or used until the person agrees (NDPA). Opt-out via stop suppresses every future message.

Never prays or counsels

Captures prayer & pastoral needs and refers to a real human — never spiritual advice itself.

Scam-proof with money & codes

Never reads an OTP, never sends money to a new/unknown account, never acts on "it's the pastor, urgent" pressure.

Danger → a human, fast

Abuse, self-harm, a child in danger → stay calm, don't fix it, escalate to a pastor and point to help (112).

Confirmation gates

Collecting money, messaging everyone, releasing a child, or storing sensitive data all require an explicit yes.

Guardian consent for children

Only a parent/guardian registers a child; release only to a registered guardian with pickup permission.

Special-category refusal

Health, religion, ethnicity, politics, orientation, biometrics — refused unless the person explicitly consents.

No dynamic schema

The AI never invents tables or columns — extra facts go into a governed attributes bag only.

Bounded reasoning

A step-capped tool loop — the AI can't run away with itself or loop endlessly.

Church isolation

Every church tool is walled to its own workspace; RLS deny-all means one church can never read another's data.

Tiered access

Bank-app style — an unverified church can't take money or add members until KYC is approved.

IT sees no data

The technical role can configure and fix the church but can never read members, giving, children, or prayers.
